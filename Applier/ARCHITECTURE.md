# Applier: API и запуск

Консольный Main печатает ответ ApplierCli. Обработчик получает готовый ApplierApi,
единолично разбирает URL или `cover-letter <jobs.id> [output.txt]` и возвращает
ответ без печати. API предоставляет подготовку формы и независимое написание
письма. GUI продолжает использовать существующий ApplierRunner.

Пакет coverletter содержит CoverLetterWriter. Он получает полные readable_text,
title и имя компании через read-only SQLite-запрос cover_letter_job.py:
jobs.source_job_ref → source_job_texts; source_job_texts.company_id → companies.
Python и путь базы берутся из существующего runtime.properties коллектора.
Вызывающий передаёт только внутренний jobs.id, а не текст вакансии.

Писатель передаёт готовый промпт и только resume.txt и candidate_context.md в
CodexClient / Codex Proxy. Настройки модели и учёт расхода остаются у Proxy;
Писатель переопределяет reasoning_effort на xhigh (Very High);
браузерные инструменты не включаются. JSON-обёртка letter распаковывается
внутри писателя. Файловый вариант сохраняет тот же текст в UTF-8 и возвращает
абсолютный путь. Ошибки передаются вызывающему; stdout принадлежит консоли.

Запуск одноразовый. UDS и серверный режим не реализованы; направление описано
в [Tools](../Tools/ARCHITECTURE.md). Автоматического вызова писателя из заполнения
форм нет. Подготовка формы по URL по-прежнему не требует записи в БД.

Перед генерацией писатель проверяет cover_letters в той же настроенной БД
и возвращает сохранённое письмо без вызова Codex и новой записи.
Если письма нет, генерирует и сохраняет текст: job_id → jobs.id, полный
letter_text и created_at (UTC). Запись предшествует возврату нового текста и
сохранению необязательного файла; при ошибке записи операция сообщает ошибку.
Файловый вариант записывает возвращённое письмо независимо от того, было оно
загружено из БД или сгенерировано.
На вакансию хранится одно письмо: job_id — первичный ключ cover_letters.
Python-помощник использует общий механизм миграций перед чтением и записью.
Миграция 045_one_cover_letter_per_job.sql оставляет последнее письмо, если
в старой БД было несколько записей для одной вакансии.
