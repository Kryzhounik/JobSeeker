# Applier: API и запуск

## Текущее состояние

Applier готовит заявку. Java API — `ApplierRunner.run(vacancyUrl)`;
консольный `Main.execute(args)` разбирает один URL, вызывает этот API и
выводит результат. GUI обращается через `DriverApi.prepareApplication(url)`
к тому же API. Действующий контракт описан в [README.md](README.md) и
[REQUIREMENTS.md](REQUIREMENTS.md).

Консольный запуск остаётся одноразовым: одна операция на запуск процесса.
Долгоживущая JVM GUI и сохраняющийся браузер сами по себе не предоставляют
внешнего командного входа в Applier. Обработчик команд с отделённым выводом
и UDS-подключение пока не реализованы.

## Согласованное расширение, реализация отложена

У модуля будет две операции: подготовка заявки и написание cover letter.
Писатель размещается отдельным пакетом внутри Applier; независимый вызов
для ручного аплая не требует отдельного Maven-модуля.

Для письма предусматриваются текстовый результат и файловый вариант.
Java API может вернуть текст либо путь к сохранённому файлу; консольный вход
может вывести текст либо этот путь. Конкретные перегрузки, формат файла,
способ генерации и инструкция писателя будут определены при следующем
обсуждении этой операции. Сейчас писатель не реализуется.

CLI-обработчик должен вызывать готовый Java API и возвращать ответ независимо
от консоли. Общий CLI проекта продолжает делегировать разбор команд модулям.
Пока сохраняется одна операция на запуск; переход к повторным вызовам и
доступу к работающей JVM отложен.

Общее решение для повторного использования API, отделения ответа от
`System.out`, UDS-адаптера и Python-клиента находится в
[архитектуре Tools](../Tools/ARCHITECTURE.md). Оно сохраняет существующую
последовательность бизнес-операций. Задача реализации имеет приоритет LOW
в [бэклоге проекта](../BACKLOG.md#next); задача писателя отдельно находится
в [бэклоге Applier](BACKLOG.md).
