# Applier backlog

Примечание: пока Apply не расходует заметную часть общего бюджета. Все идеи
ниже имеют низкий приоритет; вернуться к ним, если расход на заполнение заявок
станет существенным. Это варианты для изучения, а не согласованный план реализации.

## LOW: Выжимка из резюме

Рассмотреть компактный контекст с контактами, опытом с датами, навыками и
образованием вместо полного текста CV. Сохранить факты, необходимые для ответов
в форме. Полный PDF нужен для прикрепления: достаточно передавать агенту путь,
не добавляя содержимое PDF в контекст. Передача PDF по пути уже используется.

## LOW: Подгрузка подробностей по необходимости

Рассмотреть передачу основных данных сразу, а подробных описаний проектов и
редко нужных разделов — по запросу агента. Оценить, окупает ли сокращение
контекста дополнительные обращения и усложнение. Небольшие `facts.md`,
`resume.ini` и выжимку может быть проще передавать целиком.

## LOW: Сокращение ответов браузерных инструментов

Изучить встроенные возможности Playwright MCP: снимок нужной области через
`browser_snapshot(target=...)`, поиск элементов через `browser_find`, ограничение
глубины снимка и отключение автоматических снимков через `--snapshot-mode none`.
Полный снимок можно запрашивать, когда компактного представления недостаточно.

Также рассмотреть исключение меню, футера, повторяющихся и посторонних блоков
из ответа MCP до передачи модели. Сохранять подписи полей, типы, значения,
варианты выбора, обязательность, ошибки и кнопки текущего шага. Предварительная
разметка игнорируемых блоков полезна, только если по ней текст исключается из
ответа инструмента: пометка «игнорировать» в уже переданном контексте токены
не экономит. Сокращение выполняется на стороне MCP, где формируется ответ;
Java Applier сейчас не обрабатывает промежуточные ответы инструментов.
