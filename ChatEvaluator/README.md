# ChatEvaluator

Дополнительная независимая проверка соответствия вакансии перед подачей заявки.
Модуль отправляет ссылку на выбранную вакансию в существующий диалог ChatGPT
через Playwright и возвращает полученный ответ для отображения в JavaFX GUI.

В этом диалоге уже накоплены знания об опыте, предпочтениях и обстоятельствах
пользователя. Цель — получить второе мнение с этим контекстом в дополнение
к анализу Codex в Seeker. Новый запрос к Codex или API без истории диалога
не заменяет этот сценарий.

Для тестирования и диагностики предусмотрен запуск того же оценивателя
через исполняемый JAR с минимальным CLI (новый обязательный пункт 4 плана).
GUI и CLI должны использовать один `ChatEvaluatorRunner.run(url)`.
CLI нужен исполнителю для проверок; для обычной ручной оценки проще
открыть сам диалог ChatGPT.

ChatEvaluator находится рядом с Applier: оценка вакансии и подготовка формы —
отдельные действия. Для подключения к браузеру используется существующий
`ManagedBrowser` из Applier.

Документация для реализации и пошагового ревью:

- [REQUIREMENTS.md](REQUIREMENTS.md) — поведение и границы задачи.
- [ARCHITECTURE.md](ARCHITECTURE.md) — минимальное устройство модуля.
- [PLAN.md](PLAN.md) — порядок реализации с обязательной остановкой после каждого пункта.

Ссылка на выбранный пользователем диалог сохранена в локальном файле
`Data/chat_evaluator/config.properties`, настройка `chat.url`.
Это рабочий диалог. Для всех живых проверок и отладки используется отдельный
тестовый диалог, предоставленный пользователем; его ссылка сохранена в том же
локальном файле под ключом `chat.test.url`. Модуль читает только `chat.url`.

Перед явно запрошенной живой проверкой временно установить значение
`chat.test.url` в `chat.url`, сохранив рабочее значение, и сверить адрес открытого диалога.
После проверки восстановить рабочее значение, в том числе при ошибке.
Правила оценки и контекст в тестовом диалоге пользователь подготавливает
заранее; модуль отправляет только URL вакансии.

Автоматические тесты — только юнит-тесты без браузера, реальной сессии
и отправок в ChatGPT. Интеграционные тесты с реальным диалогом не добавлять
и не запускать, включая тестовый диалог. Живые проверки выполняются отдельно
по явному указанию пользователя; обычное ревью не запускает GUI или диалог.

Пункт 3 плана — **необязательная** живая проверка через GUI. Для приёмки
подключения GUI обязательны ревью кода, успешная сборка и подходящие
имеющиеся юнит-тесты. Если GUI-прогон пропущен или его невозможно выполнить
инструментом управления окном, это явно отмечается в отчёте и не блокирует
приёмку реализации. Ошибки такого инструмента не считаются ошибками GUI;
его диагностика и ремонт не входят в задачу.

## Настройка и запуск

Модуль использует общий управляемый браузер через `ManagedBrowser`.
Каталог профиля берётся из `profile.directory` в
`Driver/collector/java_linkedin/runtime.properties`, канал браузера — из
`browserChannel` в `Driver/collector/config/linkedin.properties`
(по умолчанию `chrome`). Используется существующая сессия ChatGPT в этом
профиле; автоматического входа нет. Если понадобится вход, сначала
согласовать действие с пользователем.

После изменений Java-кода выполнить из корня репозитория:

```powershell
mvn -f GUI/JavaFX/pom.xml compile
```

Затем открыть `GUI/JavaFX/SeekerJobs.exe`. Существующий лаунчер использует
классы из `target/classes` и библиотеки из `target/dependency`; при отсутствии
готовой сборки следовать `GUI/JavaFX/README.md`. Если GUI уже открыт,
перезапустить его, чтобы загрузить новые классы.

Выбрать вакансию и нажать `GPT Eval` рядом с `Apply`. Во время фонового
ожидания строка состояния показывает `Waiting for ChatGPT evaluation...`.
После успешного завершения появляется `ChatGPT evaluation complete`
и отдельное окно с полным текстом ответа. Поле доступно для выделения
и копирования, длинный ответ — для прокрутки. При ошибке показывается
стандартное окно `GPT Eval failed`.

Диалог и браузер остаются открытыми. Оценка ChatGPT не меняет статус вакансии
и оценки Seeker. Отдельное сохранение ответа в модуле не реализуется.

## CLI для тестирования и диагностики — пункт 4

**Статус: запланирован. Запускаемый JAR по этому контракту ещё не реализован.**
Наличие `main` в исходнике сейчас не заменяет сборку готового JAR.

После выполнения пункта 4 сборка и вызов из корня репозитория должны выглядеть так:

```powershell
mvn -f ChatEvaluator/pom.xml package
java -jar ChatEvaluator/target/chat-evaluator.jar --help
java -jar ChatEvaluator/target/chat-evaluator.jar "<vacancy-url>"
```

При запуске из другой директории передать тот же корень репозитория:

```powershell
java -Dseeker.projectRoot="<absolute-project-root>" -jar "<absolute-jar-path>" "<vacancy-url>"
```

Минимальный CLI принимает один URL вакансии. stdout содержит полный исходный
ответ, stderr — ошибки и диагностику; вывод UTF-8. Код завершения `0` означает
ответ или справку, `1` — ошибку оценивания, `2` — неверные аргументы.
`--help` и ошибки аргументов не запускают браузер и не отправляют сообщения.

В JAR должны входить необходимые runtime-зависимости. Для запуска нужен
Java 21 или новее, локальные настройки и профиль браузера; Maven, ручной
classpath, JavaFX и jpy при запуске не требуются. Браузер и Playwright
остаются частью того же сценария.

Перед проверочной отправкой установить тестовую ссылку из `chat.test.url`
в `chat.url` по правилам выше, затем восстановить рабочую настройку.
GUI и CLI используют одинаковые настройки, профиль браузера, селекторы,
таймауты и код получения ответа. Различия — получение URL из аргумента
вместо выбранной строки и вывод ответа в консоль вместо окна.
Живые вызовы выполнять только по необходимости; автоматические тесты
с реальной сессией не добавлять.
