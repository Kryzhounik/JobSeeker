# Устройство ChatEvaluator

## Общий сценарий

GUI вызывает `DriverApi.evaluateWithChatGPT(url, jobId)`, который обращается к
`ChatEvaluatorRunner.run(root, url, jobId)` и возвращает `GptEvaluation.Result`.
Входы `DriverApi.evaluateWithChatGPT(url)` и CLI используют
`ChatEvaluatorRunner.run(root, url)` и возвращают полный текст ответа.
CLI определяет корень через JVM-свойство `seeker.projectRoot`
(по умолчанию текущая директория). Все входы выполняют общую операцию
`GptEvaluation` из модуля ChatEvaluator, включая сохранение.

## Независимая задача GUI и сохранение

`MainController` фиксирует `job_id`, URL и название выбранной вакансии,
управляет одним активным запуском через собственные исполнитель, флаг
занятости и JavaFX `Task`. Общий `operationRunning` не участвует. Остальные
операции GUI продолжают работать. При закрытии GUI задача отменяется,
исполнитель останавливается; восстановления после перезапуска нет.

`GptEvaluation.run(url)` находит `job_id` по точному URL через `Store.findJobId`
и вызывает `run(url, jobId)`. GUI использует второй вход с уже известной парой
URL/ID; её согласованность обеспечивает GUI, повторного поиска нет.
При известном ID операция сначала читает сохранённый результат через `Store.load`.
Если он есть, возвращает его вместе с исходным временем до любых сетевых и
браузерных действий; повторной записи нет. Только при отсутствии результата
вызывается общая браузерная логика `ChatEvaluatorRunner`, фиксируется время
получения через `Instant.now()` и сохраняется ответ, если ID известен.
Если URL не найден, результат возвращается без ошибки и без записи в БД.
В этом месте оставлен TODO на задачу GPT-001 из `BACKLOG.md`: получить и создать
вакансию без агентных оценок, затем сохранить уже полученный ответ GPT.
Создание вакансии сейчас не выполняется.
Класс не управляет запусками и не зависит от JavaFX. Очереди сейчас нет.

Путь поиска и хранения: `GptEvaluation → PythonEvaluationStore →
Driver/db/gpt_evaluations.py`. Короткие вызовы существующего Python-слоя БД
используют `python.executable` из runtime-настроек. Запросы и ответы передаются
как внутренний UTF-8 JSON через stdin/stdout процесса; этот протокол не
попадает в stdout CLI. Поиск завершается до вызова ChatGPT, а соединение закрывается.
После получения ответа отдельный вызов выполняет UPSERT по `job_id`
и завершает транзакцию до возврата успеха. Чтение сохранённой оценки также
выполняется отдельным коротким вызовом, а при наличии ответа браузерный путь
вообще не начинается. Во время ожидания ChatGPT нет
процесса БД или открытого соединения. Дополнительная JVM не нужна.
Чтение доступно через `ClientData.loadGptEvaluation(jobId)` и Python-функцию
`load_gpt_evaluation`; отсутствие записи возвращается как `Optional.empty()`
или JSON `null` соответственно.

Таблица `job_gpt_evaluations` создаётся базовой схемой и миграцией
`041_job_gpt_evaluations.sql`. `job_id` — первичный и внешний ключ на
`jobs.id` с `ON DELETE CASCADE`; `answer` хранит полный текст,
`evaluated_at` — время получения в формате ISO 8601 UTC. Повторный вызов
читает запись без её изменения; ошибка не удаляет предыдущий ответ.

`GptEvaluationProgressPane` расширяет `BackgroundProcessPane` и использует
общую область фоновых процессов. Состояние `COMPLETED` устанавливается
после чтения прежнего ответа или сохранения нового. Ошибка оценки или хранения
даёт `FAILED` в той же
панели. `GptEvaluation.SaveException` отличает ошибку записи и удерживает
полученный текст: его можно показать в существующем окне без повторного
вызова ChatGPT. Обычное окно ответа открывается после чтения либо успешного
сохранения.
Панель отвечает только за отображение; доступ к БД и выполнение находятся
вне неё и контроллера.

CLI принимает только один URL. Найденная вакансия получает сохранённый ответ;
для отсутствующей возвращается текст без сохранения. Отдельного CLI-входа
с ID нет. stdout/stderr и коды завершения сохраняют прежний контракт;
ошибка записи после полученного ответа даёт stderr и код `1`, без повторной отправки.

## Браузерный сценарий

`ManagedBrowser` из Applier запускает или подключает управляемый Chrome.
`LinkedInJobAvailability` из Tools выполняет HTTP-запрос и классифицирует
вакансию. ChatEvaluator управляет временной браузерной проверкой при 429
и взаимодействием с ChatGPT. Зависимости подключены обычными Maven-артефактами;
копирования исходников между модулями нет.

Для фоновой вкладки вакансии включается CDP-эмуляция фокуса без вывода окна
на передний план. Навигация и ожидание описания ограничены 30 секундами каждое.
Открытая вкладка диалога ChatGPT используется без перезагрузки. После
готовности истории выполняется один DOM-клик доступной кнопки отправки.
Подтверждение нового сообщения ожидается 15 секунд, его завершённый ответ —
до 180 секунд. Связь запроса и ответа проверяется по ID сообщений и turn.

## Настройки

Пути указаны относительно корня репозитория.

| Файл | Ключ | Назначение |
| --- | --- | --- |
| `Data/chat_evaluator/config.properties` | `chat.url` | Рабочий диалог ChatGPT |
| `Data/chat_evaluator/config.properties` | `chat.test.url` | Диалог для живых проверок; сам по себе не переключает `chat.url` |
| `Driver/collector/java_linkedin/runtime.properties` | `profile.directory` | Каталог профиля браузера |
| `Driver/collector/config/linkedin.properties` | `browserChannel` | Канал браузера, по умолчанию `chrome` |

Используется существующая сессия профиля. При необходимости пользователь
входит в ChatGPT или LinkedIn вручную; автоматического логина нет.

## Сборка и запуск

Модуль входит в Maven reactor `Driver/pom.xml`. Нужна Java 21 или новее.
Из корня репозитория:

```powershell
mvn -f Driver/pom.xml -pl :chat-evaluator -am package
java -jar ChatEvaluator/chat-evaluator.jar "<vacancy-url>"
```

Тонкий JAR подключает зависимости из общего `libs/` через манифест.
Каталог должен сохранять расположение относительно JAR; Maven, ручной
classpath, JavaFX и jpy при запуске CLI не нужны.

Для другой рабочей директории:

```powershell
java -Dseeker.projectRoot="<absolute-project-root>" -jar "<absolute-jar-path>" "<vacancy-url>"
```

Для сборки GUI сначала установить модули командой
`mvn -f Driver/pom.xml install`, затем выполнить
`mvn -f GUI/JavaFX/pom.xml package`. Запуск и подготовка лаунчера описаны
в `GUI/JavaFX/README.md`. После пересборки открытый GUI нужно перезапустить.
