# План реализации ChatEvaluator

## Обязательные остановки

**Пункты этого плана — границы исполнения и ревью. После выполнения КАЖДОГО
пункта исполнитель ОБЯЗАН остановиться.**

В отчёте указать номер выполненного пункта, изменения, проведённую проверку
и её фактический результат. Дальше ждать ответа пользователя: он решает,
проводить ревью, тестировать, исправлять или начинать следующий пункт.

**Не начинать следующий пункт без явного указания пользователя.** Одобрение
плана целиком, успешный тест, собственное ревью или отсутствие новых сообщений
не разрешают продолжение. Пункты нельзя выполнять параллельно или делать
следующий «заодно». После исправлений снова показать результат и остановиться.

Реализацию выполняет отдельный агент. До начала он читает `REQUIREMENTS.md`,
`ARCHITECTURE.md` и применимые `AGENTS.md`. В текущем каталоге пока только
документация; ни один пункт реализации ещё не выполнен.

## Пункты

### 1. Рабочий модуль без GUI и первая живая проверка

Ссылка на целевой диалог уже предоставлена и сохранена в
`Data/chat_evaluator/config.properties`, ключ `chat.url`.
Начать пункт по указанию пользователя агенту-исполнителю.

Реализовать минимальный Java-модуль с чтением локальной настройки адреса диалога
и входом `run(String vacancyUrl)`. Переиспользовать существующий
`ManagedBrowser`. На реальной странице определить нужные элементы и признак
завершения ответа; отправить в существующий диалог одну ссылку на вакансию,
дождаться нового законченного ответа и вернуть весь его текст.

Вопрос входа в ChatGPT отложен до живого запуска. Если в используемом
браузере потребуется вход, сообщить пользователю фактическую ситуацию
и определить способ вместе с ним. Механизм логина заранее не реализовывать.

Проверить вызовом самого модуля без GUI. В отчёте показать URL проверенной
вакансии, отправленное сообщение и полученный ответ. Подтвердить, что ChatGPT
смог оценить вакансию по ссылке. Открытие браузера или отправка сообщения
без получения ответа не означают завершения пункта.

Если этот путь не работает, показать конкретное препятствие и остановиться
для решения пользователя. Не подменять URL текстом вакансии, не создавать
новый диалог и не переключаться на API самостоятельно.

**ОСТАНОВКА. Показать результат пункта 1 и ждать решения пользователя.**

### 2. Подключение к JavaFX GUI

Начать только по явному указанию пользователя после ревью пункта 1.
Кнопка и представление результата уже согласованы ниже.

Подключить исходники ChatEvaluator к существующей сборке GUI. Добавить
кнопку `GPT Eval` рядом с `Apply` для выбранной вакансии, вызов готового модуля
и отдельное окно с полным текстом ответа и прокруткой. Логику работы с браузером и настройкой
диалога оставить в модуле. Использовать существующие механизмы GUI
для фоновых операций и сообщения об ошибке.

Собрать GUI и проверить подключение действия и показ всего ответа.
Сохранение результатов и отдельную систему асинхронных задач не добавлять.
Существующий фоновый вызов нужен только для того, чтобы ожидание ответа
не блокировало GUI. В чат по-прежнему отправляется только URL вакансии.

**ОСТАНОВКА. Показать результат пункта 2 и ждать решения пользователя.**

### 3. Живая проверка полного пути из GUI

Начать только по явному указанию пользователя после ревью пункта 2.

Выбрать другую вакансию и запустить проверку кнопкой `GPT Eval` рядом с `Apply`.
Сверить отправленную ссылку, новый законченный ответ в том же диалоге
и весь текст в отдельном окне GUI. Убедиться, что интерфейс остаётся отзывчивым,
чат открыт, а статус и оценки вакансии не изменились.

В отчёте привести конкретный результат полного прогона и оставшиеся
наблюдаемые ограничения, если они есть. Уточнить README по фактическому
способу настройки и запуска. Не добавлять улучшения за пределами требований.

**ОСТАНОВКА. Показать результат пункта 3 и ждать итогового ревью пользователя.**
