# Контракт ChatEvaluator

## Оценивание

- Вход — один URL вакансии. В существующий диалог ChatGPT передаётся только
  этот URL, без дополнительных инструкций, текста вакансии и оценок Seeker.
- Перед отправкой проверяется доступность вакансии и приём заявок. Один
  HTTP-запрос использует общий с `Check LinkedIn` классификатор из Tools.
  Только при HTTP 429 выполняется дополнительная проверка в фоновой вкладке
  управляемого браузера с существующей сессией. Временная вкладка закрывается.
- Отправка разрешена только при `available`. Закрытая/недоступная вакансия,
  требование входа, повторный 429 или ошибка проверки останавливают вызов.
- Нужно подтвердить новое сообщение пользователя с точным URL и новым ID,
  затем получить завершённый ответ именно его turn с новым ID ответа.
  Повтор того же URL также требует нового сообщения. Старые и промежуточные
  ответы результатом не считаются; автоматической повторной отправки нет.
- Результат — полный исходный текст ответа без пересказа. GUI показывает его
  в отдельном окне с копированием и прокруткой; ожидание не блокирует интерфейс.
- История диалога сохраняется, браузер и диалог остаются открытыми.
  Подача заявки не запускается, статус вакансии и оценки Seeker не меняются.

## Фоновая оценка и хранение в GUI

- GPT Eval — независимая фоновая операция со своим исполнителем и состоянием.
  Она не использует общий `operationRunning`: остальные действия GUI остаются
  доступны. Одновременно разрешена одна оценка; повторный запуск во время
  выполнения недоступен. Очередь — ближайшее ожидаемое улучшение, но сейчас
  не реализуется. Выполнение одной оценки отделено от управления запусками.
- При запуске фиксируются ID, URL и название вакансии. Смена выбранной строки
  не влияет на сохранение и окно результата. Задача живёт вместе с GUI;
  продолжения после закрытия и автоматического возобновления нет.
- Таблица `job_gpt_evaluations` содержит `job_id` (первичный и внешний ключ
  на `jobs.id`, `ON DELETE CASCADE`), полный `answer` и `evaluated_at` — время
  получения ответа в UTC. Базовая схема и миграция создают одну запись на вакансию.
  Повторный успех обновляет ответ и время. Ошибка не удаляет предыдущий ответ.
- Сохранение и чтение по `job_id` выполняются через слой БД проекта вне
  GUI-контроллера. Во время ожидания ChatGPT нет открытой транзакции или
  блокировки объекта доступа к БД. Отсутствие сохранённого ответа — штатный результат чтения.
- Для прогресса используется существующий `BackgroundProcessPane`.
  После успешного сохранения ответа панель получает `COMPLETED`; ошибка
  оценки или записи отображается в той же панели как `FAILED`.
- Если ответ получен, но запись не удалась, ошибка явно сообщает о сохранении.
  Полученный текст доступен в существующем окне ответа. Сообщение в ChatGPT
  повторно не отправляется. Успешный ответ показывается после сохранения.
- Индикаторы и цвета строк вакансий, открытие сохранённой оценки из строки,
  отдельная JVM и пакетное выполнение сейчас не реализуются.

## CLI

CLI служит для диагностики и использует общий с GUI сценарий. Единственный
аргумент — HTTP(S)-URL вакансии. Отдельной команды справки нет.
CLI не ограничен вакансиями из базы и не сохраняет оценку по `job_id`;
сохранение относится к GUI-сценарию.

stdout содержит полный ответ, stderr — ошибки; кодировка UTF-8. Коды:
`0` — ответ получен, `1` — ошибка оценивания, `2` — неверные аргументы,
отклонённые до обращения к браузеру.

## Проверки и ограничения

- Автоматические тесты — только изолированные юнит-тесты без браузера,
  реальной сессии и отправок в ChatGPT. При обычном ревью не повторять их
  без конкретной причины. Интеграционные автотесты с реальным ChatGPT
  не добавлять и не запускать, включая тестовый диалог.
- Живые проверки выполняются отдельно по явному указанию пользователя,
  только в предоставленном им тестовом диалоге. Перед проверкой сохранить
  `chat.url`, временно подставить `chat.test.url` и сверить адрес вкладки.
  После проверки восстановить рабочую настройку, в том числе при ошибке.
  Тестовый диалог с контекстом пользователь подготавливает заранее.
- Полный живой прогон через GUI необязателен.
- Доступность вакансии в локальном браузере не гарантирует её доступность
  самому ChatGPT: он может вернуть `UNCERTAIN`. Автоматически подменять URL
  текстом вакансии, новым диалогом или API нельзя.
- Пакетная обработка, очереди и сервисный API в текущую реализацию не входят.
